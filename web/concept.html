Concept card · Earned Trust in AI Code

Evidence-first review with a named owner.

The AI does the reading and shows its proof.
A named person makes every decision that matters, and signs for it.

The review factory

machine1 ProveDeterministic checks clear what can be proven, e.g. generated files.
machine2 GateDependencies, public API, secrets, build: always a human call.
AI3 ReviewOne reviewer reads what is left, against the requirement.
machine4 VerifyQuote-or-drop: claims must quote real diff lines.
machine5 RouteNamed rules, no scores, decide what reaches the owner.
human6 SignOwner answers, accepts the gaps, signs this exact commit.

Afterwards: owners spot-check findings, escapes are tracked per area, and trust is earned or withdrawn per area.

Principles

Risk

Human attention follows named rules, not a score.Policy areas are never delegated. Everything else reaches the owner only if it changes whether the requirement is met.

Hallucination

No proof, no claim.Findings must quote real code or they are deleted. Facts outside the diff need a machine probe. Spot-checks measure what slips through.

Transparency

Every item says why it reached you.What was not checked is listed on the receipt the owner signs.

Confidence

We show the kind of evidence, never a confidence number.Machine-proven › verified quote › AI claim. A percentage nobody can check is not shown.

Quality

Judged against the requirement, not the agent's story.The agent's own tests and docs are claims to check, not proof.

Trade-offs and limits

Trade-offs we chose

  • Machine-proven files skip AI review.Fast and exact, but only as good as the template they repeat, which is reviewed instead.
  • Policy changes always go to a human.Every sample agent change hit this rule. More human load, but no silent support drops.
  • One AI call per change.30–45 s and cheap, but results vary between runs. We measure that.
  • Rules instead of scores.Explainable and auditable; less nuanced than a learned risk model.

Limits we know

  • Quote-or-drop stops invented code, not wrong conclusions.False findings with real quotes still pass. Spot-checks catch them.
  • The reviewer can share the coding agent's blind spots.Deterministic gates do not depend on the AI at all.
  • Tests were not run in this reference.No .NET SDK on the review host; listed as not checked on every receipt.
  • Requirements come from the upstream issues.Not a formal requirements set with acceptance IDs.

Technology considerations

Security

The diff is untrusted input to the reviewer.Agent code could carry instructions aimed at the AI. So the reviewer has no tools and no approval power, its output is schema-bound and quote-verified, secrets are redacted before the model sees them, and the gates run without AI.

Backend

Git diff in, case file out.Python, deterministic checks, one headless model call with a JSON schema. Runs as a CI check in 30–45 s per change.

Frontend

A case file instead of a diff.Decisions first, evidence one tap away, sign-off with full name. Works on a phone.

Accountability

Signatures bind to commit and evidence hash.A new push voids the sign-off. The log is append-only.

How it scales

Per change

Cost and time stay flat; human time drops with the share proven by machine.

Per repo

Policy globs, generated-file patterns and public-API paths are configuration.

Per area

An area earns "machine-verified" after clean spot-checks, and loses it after one escape.

Outcome

Success means review time falls while reverts and incidents do not rise. See the measurements →
